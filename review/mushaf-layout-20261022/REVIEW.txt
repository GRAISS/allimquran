ALLIM Mushaf reading space and typography — 22 October 2026
Follow-up to g-karim/allimquran issue #4.

Problem and result
The reported screen used several horizontal control rows plus independently positioned microphone, account-data and journal panels. The page width was capped by viewport height, and each Quran line was fitted to a different font size.

This candidate uses one 55px navigation row, a side settings dialog and a reserved bottom row. The page can use up to 900px width and scroll naturally instead of shrinking to screen height. All words and ayah markers on a page share one fitted font size; missing page-font codes trigger a whole-page Unicode fallback instead of mixing glyph encodings. Adaptive text remains 28–52px, default 36px on phones. The existing page layout remains selectable. The font picker is disabled while adaptive mode uses its unified Unicode font.

Size, appearance, verse selectors, audio and other secondary controls move into the side dialog. Existing account-data and journal panels move there too, retaining their original DOM nodes/listeners and restoring their original positions on exit. Account errors/locks reopen the dialog; the dialog is outside the application root so account protection does not make the recovery controls inert. The page keeps a visible return control, page navigation and search. The duplicate mobile microphone is suppressed only in Mushaf mode; the original microphone and its status remain in the reserved row.
